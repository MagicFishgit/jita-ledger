# Planets Upgrade Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Turn Side hustles → Planets into a planner. Given a system and a character, it ranks every setup type by ISK a
day with upkeep beside it, says which planet does what, and values every output. Add a P0 → P4 chart. Keep every
character's colonies (stage 2), so real planets are shown, valued and set against the planner.

**Architecture:**
- **Pure rules in `src/lib`**, tested in `scripts/check.mjs`:
  - a bundle of CCP's static data, plus planet radii;
  - the fit, from exact CPU and powergrid;
  - CCP's extraction formula;
  - the kept-colonies document;
  - the planets settings document;
  - learned rates;
  - the planner;
  - a colony's real chain (stage 2).
- **Hooks and components in `src/components/hustles/`.** They reuse Industry's price, freight, home-market and
  "Show for" machinery.
- **In the cloud:** it keeps the main's colonies (stage 1) and every alt's (stage 2) as a synced document. The home
  reads gain every planetary good.

**Tech Stack:** React 18 + TypeScript + Vite; Cloudflare Worker + D1; Node's type stripping for tests (`scripts/check.mjs`,
`scripts/check-worker.mjs`); Playwright page checks (`scripts/pages.mjs`).

**Spec:** `docs/superpowers/specs/2026-10-17-planets-design.md`. Research, gitignored: `.playwright-mcp/research/planets/`:
- `mechanics.md` and `pi-static.json`: the static data's figures, and the formula;
- `scripts/fit.py`: the fit arithmetic;
- `web/ccp-dev-guide-pi.txt`: CCP's extraction guide;
- `prices.md`;
- `app-and-colonies.md`.

## Review Focus

1. **A system with planets the static data lacks** (Shattered, 713 in the universe; Scorched Barren) or with no planet
   that makes anything alone. Those planets are listed as "no planetary industry here", the setups that can't run say
   why, and nothing throws. Pinned in Task 8.
2. **A character whose skills aren't read, an Alpha, or one allowed a single planet.** Unread is said, never level 0.
   An Alpha says it can't do planetary industry. A chain counts only characters whose skills are read. Pinned in
   Tasks 8, 9 and 11.
3. **No extraction rate for a planet type** (no colonies there, nothing typed). Ranked at what the factories that fit
   could make, said as "if your extractors deliver X P0 an hour", never claimed. Pinned in Task 8.
4. **A price nobody reads** (no home row, a Jita book that failed). That output is unvalued, with its reason. The
   setup's ISK says how many outputs aren't counted, and never treats them as 0. Pinned in Tasks 8 and 10.
5. **The main's PI alerts switched off, or a Worker a version behind.** The cloud's hourly colony read still runs and
   keeps the document. A refused `colonies` or `planets` document is held back, never lost. Pinned in Tasks 4 and 5.

### Task 3: CCP's extraction formula and the two readings

  - `cycleOutputs(qtyPerCycle: number, cycleSeconds: number, cycles: number, decay = 0.012, noise = 0.8): number[]`, CCP's formula:

    out_i = floor(barWidth × qty/(1 + t×decay) × (1 + noise × max(0,(cos(qty^0.7 + t/12) + cos(qty^0.7/2 + t/5) + cos(t/2))/3)))

    Match CCP's worked example exactly. If a floor differs by a unit, follow `web/ccp-dev-guide-pi.txt`'s Kotlin and say
