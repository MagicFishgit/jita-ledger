# R&D agents: a Research tab — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A Research tab under Side hustles that teaches R&D agents, walks the main and the alt through getting them
going, and tracks their research, with a To do item past an amount and a Wallet card.

**Architecture:** Pure rules in `src/lib/research.ts` and a static-data bundle `src/data/researchAgents.json` (built by a
script, as `typeMaterials.json` is). The browser's sync keeps the main's whole standings and research in `meta`; the
cloud's hourly alt read keeps the alt's in the alt's `meta`; the tab, To do and the Wallet read them. Built in two
stages: getting started (Tasks 1–3), then tracking (Tasks 4–6).

**Tech Stack:** React + TypeScript + Vite; Cloudflare Worker + D1; ESI (`X-Compatibility-Date: 2026-08-18`); tests in
`scripts/check.mjs`, `scripts/check-worker.mjs`, pages in `scripts/pages.mjs`.

**Spec:** `docs/superpowers/specs/2026-10-03-rd-agents-design.md` (read it whole first; it carries the facts, every
state's wording, and what was cut). The research behind it: `.playwright-mcp/research/rd-agents/draft.md` (gitignored;
`rd-agents.json` and the market and skill files beside it).

This repo's plans give each task's files, interfaces, the exact values and the failing tests; implementers write the code
following the surrounding code (CLAUDE.md: match its idioms). Every task: read CLAUDE.md and the notes it names first.

## Global Constraints

- Nothing not known reads as zero: absent → "Not read yet"; empty → "No agents running" / no standing; permission missing
  → "Log in again to read your research" (main) / "Hand the cloud this login again" (alt); prices unread → "Pricing…".
- Named constants stated in the copy: `RP_PER_DATACORE` 100 ("assumed: CCP 2012; CCP's support page says 50–150 by
  field"), `DATACORE_FEE` 10,000, `ACCESS` −2 / 1 / 3 / 5, `CORP_BELOW_FACTION` 2, the formula's 20, `RATE_TOLERANCE` 2 RP
  or 2%.
- `src/lib/research.ts` and everything it imports: no `./config`, `./store`, React or DOM (Node type stripping loads it).
- The site and the Worker deploy in either order: a field the other side doesn't have yet is absent, never an error; no
  D1 migration (everything is JSON in existing docs).
- The alt's data is filed under the alt's ID, never the main's (characters-cloud.md); the browser's alt copy is read-only.
- The alt's `meta` carries no read time: its "read at" is its `sheet` job's `lastOk` from the roster.
- Stand-in research data lives in `pages.mjs` cases of its own, never in `scripts/ledgers.mjs` (check-income records it).
- Tips laid out (lead line, bullets); facts at a glance (app-conventions.md); phone width works (check-phone).
- Commit messages explain what and why; end each with
  `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>` and
  `Claude-Session: https://claude.ai/code/session_01D3Zx5fms2TWhEQgdkabhCf`.

## Review Focus

1. The alt before the cloud's first read after the Worker deploys: every figure says "Not read yet", never "no standing",
   0 RP or "No agents running".
2. A login without the research permission (the main before relogging; the alt before handing over): says what to do,
   never "No agents running".
3. Datacore prices not read yet, or a field's book empty: "Pricing…" / "–", never 0 ISK.
4. The cash-in item: never done on absence; a price fall unticks it rather than calling it bought.
5. The hourly alt read with nothing changed pushes no new revision (no read time or unsorted list in the doc).

```ts
// src/lib/research.ts
export const RP_PER_DATACORE = 100;
export const DATACORE_FEE = 10_000;
export const ACCESS: Record<1 | 2 | 3 | 4, number> = { 1: -2, 2: 1, 3: 3, 4: 5 };
export const CORP_BELOW_FACTION = 2;
export const RATE_TOLERANCE = { rp: 2, share: 0.02 };
/** Field skill type ID → its datacore's type ID: the 17 that make one (dogma 182 on the datacore). */
export const DATACORE_OF: Record<number, number>;
export type StandingRow = { id: number; type: 'agent' | 'npc_corp' | 'faction'; standing: number };
export type ResearchRow = { agentId: number; skillTypeId: number; startedAt: string; pointsPerDay: number; remainderPoints: number };
export type RdAgent = { id: number; name: string; level: 1 | 2 | 3 | 4; corp: number; faction: number; station: number; system: number; fields: number[] };
export type HelperAgent = { id: number; name: string; level: number; corp: number; division: 'security' | 'distribution'; station: number; system: number };
export function rpPerDay(o: { field: number; agentLevel: number; negotiation: number; agentStanding: number | null }): number;
/** Effective standing: null (no standing) stays null; friendly raw + (10 − raw) × 4% × Connections; negative likewise with Diplomacy. */
export function effectiveStanding(raw: number | null, connections: number, diplomacy: number): number | null;
/** Can a character use an R&D agent of this level, given its effective corporation and faction standing (null = none)? */
export function agentAccess(level: 1 | 2 | 3 | 4, corp: number | null, faction: number | null): boolean;
/** The highest R&D level open at these standings, or 0. */
export function openLevel(corp: number | null, faction: number | null): 0 | 1 | 2 | 3 | 4;
/** CCP's formula: remainder + per day × days since start. */
export function rpNow(row: ResearchRow, at: number): number;
/** Whole datacores at the cost. */
export function datacoresFor(rp: number, cost?: number): number;
/** What `units` datacores fetch walked down Jita's bids after sales tax, less the fee each; null without bids. */
export function datacoreValue(bids: { price: number; volume: number }[] | null, units: number, salesTax: number): { total: number; perUnit: number } | null;
/** Agents a character can use or nearly can, each with RP a day there and ISK a day at the field's net per datacore, best first. */
export type RankedAgent = { agent: RdAgent; field: number; datacore: number; open: boolean; rpDay: number; iskDay: number | null; jumps: number | null };
/** Every (agent, field) pair: `open` from its corporation's and faction's effective standing; RP a day at the character's
 *  skills (the field at least the agent's level, else what it would be once trained to it); ISK a day at the field's net
 *  per datacore (null while unpriced); best ISK a day first, open ones before closed. */
export function rankAgents(agents: RdAgent[], o: { skills: Record<number, number>; standings: StandingRow[] | null;
  connections: number; diplomacy: number; negotiation: number; netPerDatacore: Record<number, number | null>;
  jumpsTo: (system: number) => number | null }): RankedAgent[];
```
